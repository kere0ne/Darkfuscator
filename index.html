What every build gets

VM compiler

Readable Lua is compiled to custom bytecode that runs inside a proprietary VM. No loadstring, nothing to hook.

Obfuscator

Variable and function renaming, string encryption, control-flow flattening, dead code injection.

Per-request randomization

Opcodes, names and structure shuffle on every run, so no two payloads match.

Anti-tamper

Integrity checks detect and reject modified bytecode, with multi-layer encryption and a chunked loader.

Decompiler resistance

Standard Lua decompilers output garbage: there is no Lua bytecode to read in the first place.

Heavy junk

Up to 100k dead statements (about 900 KB) of arithmetic noise wrap every maximum build.

How it works

1

Paste your Luau or load a file on the Obfuscate page. Validate catches syntax errors with line and column.

2

Pick a preset or tune the settings: VM layers, junk, anti-tamper, environment locks.

3

Obfuscate, then copy or download the payload. Every run reshuffles the whole structure.

Happy halloween. Obfuscation makes scripts hard to reverse; it is not a security boundary. Protecting a script does not make it safe to run.
